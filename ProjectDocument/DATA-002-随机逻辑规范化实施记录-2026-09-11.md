## 1. 任务目标

DATA-002 将旧的“为每张牌生成随机 seed 后排序”替换为明确的 Fisher–Yates 洗牌，并让随机行为可以通过确定性输入验证。目标不是改变前端洗牌动画，而是固定抽牌所依赖的领域规则：

1. 每轮结果包含完整 78 张牌；
2. 不丢牌、不重复；
3. 不修改 `tarotCards` 生产源数组；
4. 算法步骤清楚，不再依赖随机排序比较；
5. 正逆位边界明确且保持旧行为；
6. 测试完全确定，不依赖偶然概率通过。

## 2. 实施前状态

原 `drawRandomDeck()` 逻辑为：

```ts
return [...tarotCards]
  .map((card) => ({ card, seed: Math.random() }))
  .sort((a, b) => a.seed - b.seed)
  .map((item) => item.card)
```

该实现不会直接修改 `tarotCards`，但存在以下工程问题：

- 随机规则依赖排序过程，不如交换算法直观；
- 为每张牌额外创建 `{ card, seed }` 对象；
- 时间复杂度由排序决定；
- `Math.random()` 被写死，无法为边界和固定排列提供确定性测试。

原正逆位规则是：

```ts
Math.random() > 0.5 ? "upright" : "reversed"
```

本任务必须保留该可观察规则，即随机值严格大于 `0.5` 才是正位，等于 `0.5` 仍是逆位。

## 3. 实现方案

### 3.1 纯随机模块

新增 `src/lib/tarot-random.ts`，只负责两项领域能力：

- `shuffleDeck(source, random)`：复制输入数组后执行 Fisher–Yates；
- `randomOrientation(random)`：根据同一随机源生成正逆位。

两者的 `random` 参数默认都是 `Math.random`，因此现有生产调用不需要修改；测试可以传入确定性随机函数。随机源注入仅用于分离不可控随机数和可验证规则，不引入类、容器或额外架构层。

### 3.2 Fisher–Yates 规则

实现从数组最后一个位置向前迭代。对于当前位置 `index`：

```ts
swapIndex = Math.floor(random() * (index + 1))
```

然后交换 `shuffled[index]` 和 `shuffled[swapIndex]`。输入首先通过展开运算复制，所有交换只发生在新数组上。

与旧实现相比：

- 不再调用 `Array.sort()`；
- 不创建中间 seed 对象；
- 只执行线性数量的交换；
- 在随机源均匀返回 `[0, 1)` 数值的前提下，每一步都从尚未固定的有效区间选取位置。

### 3.3 兼容层

`src/lib/tarot.ts` 继续对旧前端提供相同入口：

- `drawRandomDeck()` 仍返回新的 `TarotCardData[]`；
- `randomOrientation()` 仍由原路径导出；
- `TarotExperience.tsx` 的 import、调用参数和状态流程不变。

`drawRandomDeck` 也允许传入测试随机源，但所有现有调用仍使用默认的 `Math.random`。

## 4. 自动化测试

新增 `tests/data/tarot-random.test.mjs`，并让现有 `test:data` 命令运行 `tests/data/*.test.mjs`。

### 4.1 先失败证据

先加入测试再实现生产模块。首次运行失败并返回非零退出码，错误为：

```txt
ERR_MODULE_NOT_FOUND: Cannot find module 'src/lib/tarot-random.ts'
```

这证明新增用例被测试命令实际发现和执行，而不是空测试或永远成功的占位命令。

### 4.2 固定交换序列

使用四项冻结输入和随机序列 `[0, 0.5, 0.999]`，断言输出严格为：

```txt
empress, priestess, magician, fool
```

同时断言：

- 原数组内容不变；
- 返回值与原数组不是同一引用。

该测试直接固定 Fisher–Yates 的倒序有效区间交换行为。

### 4.3 250 轮牌组验证

使用确定性线性同余随机源执行种子 1～250。每轮均验证：

- 长度严格为 78；
- ID Set 大小严格为 78；
- 排序后的 ID 集合与生产牌组完全一致。

全部轮次结束后，再次确认生产 `tarotCards` 的原始顺序没有变化。

使用种子随机源是为了让失败可以稳定复现；测试没有用 `Math.random()` 制造概率性成功。

### 4.4 正逆位边界

固定以下规则：

| 随机值 | 结果 |
| ---: | --- |
| `0` | `reversed` |
| `0.5` | `reversed` |
| `0.5000001` | `upright` |
| `0.9999999` | `upright` |
