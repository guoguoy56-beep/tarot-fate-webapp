## 1. 任务目标

TEST-002 的目标是把已有数据/随机测试迁移到统一 TypeScript 测试底座，并为新前端前必须稳定的纯领域边界建立自动保护：

1. 保留 DATA-001、DATA-002 已有 7 项测试的全部断言；
2. 建立统一 `npm test`；
3. 覆盖生产牌组、随机规则、问题字符/请求字节限制；
4. 覆盖阅读请求规范化、可信牌义重建和稳定错误码；
5. 覆盖前端阅读响应、API 错误载荷和本地历史记录运行时校验；
6. 将单元测试接入现有 GitHub Actions；
7. 保持 DeepSeek 适配器、Route Handler 集成和旧前端 E2E 在后续独立任务中处理。

## 2. 实施前基线

实施前仓库已有：

- `tests/data/tarot-data.test.mjs`：4 项 Node 内置测试；
- `tests/data/tarot-random.test.mjs`：3 项 Node 内置测试；
- `npm run test:data`：只运行上述 7 项；
- CI 在审计后执行 `npm run test:data`；
- 请求与牌义校验已有纯 TypeScript 模块，但没有持久化自动测试；

- localStorage 只保护 JSON 解析异常，合法 JSON 但错误结构仍会被强制转换为 `ReadingRecord[]`。

## 3. 测试工具接入

### 3.1 精确依赖

使用 npm `11.19.1` 精确加入：

```text
vitest@5.0.1
vite@8.3.0
```

两者与项目 Node.js 24 基线兼容。`package-lock.json` 已同步更新，干净 `npm ci` 可复现安装 416 个包。

### 3.2 Vitest 配置

新增 `vitest.config.mts`：

- 明确使用 ESM 配置语义，不修改整个项目的 `package.json#type`；
- 默认使用 Node 环境，不引入 jsdom；
- 只收集 `tests/unit/**/*.test.ts`；
- 将 `@` 映射到 `src`，与应用的 TypeScript 路径一致；
- 每项测试恢复 Mock、环境变量和全局替身，降低测试间污染风险。

首轮使用 `.ts` 配置时，Vite 给出“ESM 语法由 CommonJS 配置加载”的未来兼容警告；改为 `.mts` 后警告消失，没有通过环境变量隐藏警告。

### 3.3 命令统一

`package.json` 当前提供：

```text
npm test            -> vitest run
npm run test:watch  -> vitest
```

原 `test:data` 脚本和两份 `.mjs` 文件已移除，避免两套单元测试运行器长期并存。

## 5. 最小生产代码调整

### 5.1 阅读响应与错误守卫

新增 `src/lib/reading-response.ts`，将以下纯函数从大型 React 组件移出：

- `isReadingResponse`：要求 `past`、`present`、`future`、`summary` 均为非空字符串；
- `getReadingApiError`：只接受公开错误码、非空消息和布尔 `retryable`。

`TarotExperience.tsx` 只改为导入这两个函数，成功请求、失败回退文案和界面状态流程未改变。未知或畸形错误载荷继续降级到既有通用错误提示。

### 5.2 本地记录运行时校验

`src/lib/storage.ts` 新增 `isReadingRecord`，检查：

- ID、问题、时间和总结为非空字符串；
- spread 恰好包含三张牌；
- past/present/future 牌位合法且不重复；
- cardId 来自当前 78 张生产牌组；
- 正逆位合法；
- 每张牌的解读为非空字符串。

读取 localStorage 时，只返回通过校验的记录；无浏览器环境、空值、坏 JSON、非数组、错误对象或部分坏记录均安全降级，不再把任意 JSON 强制断言为 `ReadingRecord[]`。

本任务没有引入 schema version、迁移框架、删除单条记录或数据导出；这些仍属于 STORE-001～003。
