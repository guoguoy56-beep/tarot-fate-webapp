## 1. 目标与基线

通过真实 `POST(Request)` 入口验证 `/api/reading` 的 HTTP 契约，让请求解析、可信卡牌重建、领域校验、上游结果映射和日志一起接受自动验证。

实施前统一 `npm test` 已运行 9 个文件、103 项测试，但 Vitest 只收集 `tests/unit/`，没有可持久执行的 Route Handler 集成测试。

## 2. 实施范围

新增 `tests/integration/reading-route.test.ts` 的 32 项测试，并将 `tests/integration/**/*.test.ts` 加入 Vitest 的收集范围。CI 继续执行同一条 `npm test`，步骤名称改为 `Run unit and API tests`，没有新增运行器或依赖。

保留以下生产实现：

- `POST` Route Handler；
- 请求流读取、UTF-8/JSON 解析与字节限制；
- 领域校验、问题规范化与本地可信牌义；
- `NextResponse` 的 HTTP 状态、头部和 JSON 序列化；
- `recordReadingMetric` 的结构化日志。

只替换 `requestDeepSeekReading`，并保留真实 `DeepSeekReadingError` 类，验证实际 `instanceof` 分支及未知异常兜底。生产代码、API 契约、依赖与锁文件未修改。

## 3. 隔离与隐私

- DeepSeek 调用通过 Vitest 模块 Mock 返回受控成功结果或异常，不复制适配器实现；适配器本身仍由 TEST-003 覆盖。
- 全局 `fetch` 替换为抛错替身，每项测试结束断言它未被调用，防止意外外联。
- 仅设置固定假 Key，不读取真实密钥；沿用既有环境变量和 Mock 恢复配置。
- 捕获真实日志函数的 `console.info` / `console.warn` 输出，检查没有用户问题、解读正文、伪造元数据、假 Key、Prompt 或内部异常标记。
- 错误响应精确断言只含公开的 `code`、非空 `message` 和 `retryable`；不允许额外的 Token 用量、模型、Provider 状态、Prompt 或异常栈进入响应。
- 日志断言检查单次事件的安全字段，不依赖进程内累计值或测试顺序。
