# STORE-004：本地 SQLite 手记与历史记录

日期：2026-11-16。状态：已实现并验证。

用户决定星空保持现状，先完善其他功能，真实 AI 解读最后接入；本轮先完成手记保存与历史管理。用户随后明确选择“直接接 SQLite”，替代原先仅用浏览器存储的实施方向。本轮没有改动星空或 3D 动画。

## 功能

- 新版手记保存完整问题、牌阵、1–5 张牌的顺序／牌位／正逆位、当时的逐牌正文与整体总结。
- 历史可查看牌面缩略图及完整内容，支持单条删除、取消删除、读取和保存失败重试；历史滚动条隐藏，长内容保留换行及滚动。
- 内容仍明确标注“示例手记”；保存的是当时展示的快照，不调用 AI，也不会随下次抽牌而改变。
- 旧版 `tarot_reading_records` 在打开历史时逐条导入。原浏览器数据保留，失败可重试。导入账本避免重复和删除后复活。
- SQLite 不再按浏览器旧格式的 20 条上限自动淘汰新版手记。

## 运行方式与边界

沿用原来的 `npm run dev` 或 `npm run build`／`npm run start`，首次访问手记接口时自动创建数据库，无需另开数据库服务。

- 默认文件：项目根目录 `data/tarot.sqlite`。数据库及 WAL／SHM 文件已忽略，不进入 Git。
- 可选进程环境变量：`TAROT_DATABASE_PATH`，测试使用独立文件，不修改 `.env.local`。
- 使用 Node 24 内建 `node:sqlite`，无新增 npm 依赖。当前 Node 24.12.0 对该模块仍显示 ExperimentalWarning；本轮按该固定环境验证，未隐藏警告。
- 当前是本机单人资料库，同一项目服务下的浏览器共享历史；没有账户隔离、云服务或跨机器同步。未来公开部署前需重新落实认证与数据归属。
- 备份时先停止项目，再保留整个 `data/` 目录；迁移电脑时数据库文件需要一并迁移。不要只复制仍在写入的主数据库文件。

## 实现

- `journal-record.ts`：版本化快照与两端共用校验，兼容旧手记日期。
- `cosmic-journal.ts`：展示与保存共用的示例内容生成，覆盖现有八种牌阵。
- `journal-db.ts`：`journals`、`journal_cards`、`legacy_imports` 三表；事务、外键级联、参数化 SQL、不可变幂等保存与稳定时间排序。
- `/api/journals`：GET 读取、POST 保存／导入、DELETE 单条删除；128 KiB 流式请求上限、同源检查、错误脱敏与禁止缓存。
- `journal-storage.ts`：浏览器异步调用及旧记录导入；不把服务失败吞成空历史。
- `CosmicHistory.tsx`：加载／错误／空状态、详情及删除反馈。

生产联调发现 Next 内部请求 URL 的 localhost 与实际访问 Host 不一致，因此同源检查以实际 Host 为准，不信任转发 Host。保存完成前禁用历史入口；删除完成后通知父级刷新，避免关闭重开后的异步旧状态。
