## 1. 任务目标

DATA-001 的目标是把塔罗牌领域数据和真实牌面资源从“人工看起来完整”变为“每次提交都能自动证明完整”。本次检查直接读取应用实际使用的 `tarotCards`、`tarotCardMap` 和 `public/cards/rws/`，不维护一份容易与生产代码分叉的测试副本。

验收条件：

1. 牌组总数严格等于 78；
2. 卡牌 ID 唯一且 `tarotCardMap` 能完整索引每张牌；
3. 包含 22 张大阿卡纳和 56 张小阿卡纳；
4. 大阿卡纳编号完整覆盖 0～21；
5. 权杖、圣杯、宝剑、星币各有 14 张，编号完整覆盖 1～14；
6. 中英文牌名、基础含义、正位关键词和逆位关键词均非空；
7. 78 条图片路径唯一、格式正确并与资源目录精确对应；
8. 每张图片是实际存在、非空且具有完整 JPEG 首尾标记的文件；
9. 数据检查作为 GitHub Actions 的硬门禁执行。

## 3. 测试工具决策

本任务使用 Node.js 24 自带的 `node:test` 和 `node:assert/strict`：

- 项目已经固定 Node.js 24，不需要新增 Vitest、Jest、tsx 或其他依赖；
- `src/data/tarotCards.ts` 只使用可擦除的 TypeScript 语法，且其类型依赖通过 `import type` 引入，因此 Node 24 可以直接加载实际生产数据；
- 测试文件使用 `.mjs`，避免将本次局部测试工具决定扩展成全项目模块类型迁移；
- `--disable-warning=MODULE_TYPELESS_PACKAGE_JSON` 只关闭直接加载当前 `.ts` ES Module 时的已知模块类型提示，不关闭断言、测试失败或其他警告；
- TEST-001 仍需在后续结合 API Mock、React 和浏览器 E2E 需求决定最终测试工具组合。本次选择只服务于无第三方依赖即可完成的 DATA-001。

Node.js 官方文档说明 `node:test` 是稳定测试运行器，失败测试会让进程返回非零状态；Node.js 24 也支持直接执行只包含可擦除语法的 TypeScript 文件。参考：

- <https://nodejs.org/docs/latest-v24.x/api/test.html>
- <https://nodejs.org/docs/latest-v24.x/api/typescript.html>

## 4. 测试结构

新增 `tests/data/tarot-data.test.mjs`，包含 4 个公开行为测试。

### 4.1 牌组数量、ID、图片路径与 Map

- `tarotCards.length === 78`；
- ID Set 大小严格等于 78；
- 图片路径 Set 大小严格等于 78；
- `tarotCardMap.size === 78`；
- 每个 ID 从 Map 取回的对象必须是对应生产卡牌。

### 4.2 大小阿卡纳结构

- 大阿卡纳严格等于 22 张且 `suit === null`；
- 大阿卡纳编号排序后严格等于 0～21；
- 小阿卡纳严格等于 56 张；
- 四个合法花色分别严格等于 14 张；
- 每个花色编号排序后严格等于 1～14。

这些断言不仅检查总数，也能发现“总数仍为 78，但某张牌被错误分类或编号重复”的问题。

### 4.3 必填内容

逐张验证：

- `id`；
- `nameCn`；
- `nameEn`；
- `meaning`；
- `uprightKeywords` 数组及每个关键词；
- `reversedKeywords` 数组及每个关键词。

文本必须是字符串，并且清理首尾空白后仍非空；关键词数组至少包含一项。

### 4.4 牌面资源

- 生产数据中的路径必须符合 `/cards/rws/*.jpg`；
- 资源目录必须有且只有生产数据引用的 78 个 JPG 文件；
- 每条路径必须解析为真实文件；
- 文件大小至少为 4 字节；
- 文件必须以 JPEG `FF D8` 开始并以 `FF D9` 结束。

因此，删除或改名图片、写错路径、留下未被数据引用的替代 JPG、提交空文件或明显截断文件都会使检查失败。

## 9. 已知边界

JPEG 首尾标记可以发现空文件、错误格式和部分截断，但不能替代完整图片解码或人工视觉检查。图片加载性能和视觉质量分别留到 PERF 与前端专项阶段。

Node 内置 TypeScript 支持不读取项目 `tsconfig.json` 的路径别名；本测试能够直接导入 `tarotCards.ts`，是因为该文件运行时没有路径别名依赖。未来若生产数据模块引入运行时 `@/` 导入，应在 TEST-001 选型时统一解决，而不是向当前命令堆叠临时加载器。
