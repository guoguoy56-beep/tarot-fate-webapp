# DEPLOY-001 香港 ECS 受限预览部署

日期：2026-11-16。目标：接续 Antigravity 已安装和构建的环境，完成宝塔可视化管理及当前版本的受限预览。实际公网地址、实例编号及访问来源仅记录在已忽略的 `output/deployment/Codex-部署验收-2026-11-16.txt`，本文不包含登录凭据。

## 已部署状态

- 中国香港 Ubuntu 22.04 ECS，2 vCPU / 4 GiB / 40 GiB；宝塔 12.0、Nginx、Node.js 24.22.3、npm 11.19.1。
- 单入口：宝塔 Nginx → `127.0.0.1:3000` → 单个 Next.js 16.4.2 生产进程。没有开放应用的 3000 端口。
- 宝塔 Node 项目为 `tarot-preview`，目录 `/www/wwwroot/tarot-preview`，自定义启动命令为 `node /www/wwwroot/tarot-preview/node_modules/next/dist/bin/next start -p 3000 -H 127.0.0.1`。
- 使用宝塔原生支持的非 root 用户 `www`。原 `tarot` 用户启动时无法写入宝塔共享 PID 目录，且遗留了未被面板识别的进程；核验进程所属目录后正常终止，再切换用户及应用目录所有者。没有修改宝塔厂商代码或开放共享 PID 目录的全局写权限。
- 独立 SQLite 路径为 `/var/lib/tarot/tarot.sqlite`；目录权限 750，数据库当前权限 640，所有者 `www:www`。运行数据不在上传包中，不随重新构建覆盖。
- 环境保留 `DEEPSEEK_READING_ENABLED=false` 和上述数据库路径；没有上传本地真实密钥，没有执行真实付费 AI 请求。

## 访问限制

当前是无域名的 HTTP 预览，未完成真实登录或用户隔离。公网安全组的 TCP 80 仅允许用户当前直连及浏览器代理出口地址；Nginx 的 `extension/tarot-preview/preview-access.conf` 再次限制相同来源，并允许本机回环用于验收，其余来源拒绝。IP 白名单不等于应用账号认证；正式开放需继续执行 AUTH-001。

站点主配置为 `/www/server/panel/vhost/nginx/node_tarot-preview.conf`。转发保留 `Host $http_host`，覆盖 `X-Real-IP`、`X-Forwarded-For` 为连接来源，设置 `X-Forwarded-Proto`，关闭代理缓存。更换域名或重新生成宝塔配置后，需要核对这些设置和白名单包含关系。

`/api/journals` 返回 `Cache-Control: no-store`。实测 `.env.production.local`、`package.json`、`.git/config` 均返回 404；未授权来源伪造 `X-Forwarded-For` 仍返回 403。没有创建另一套代理或开放数据库端口。

## HTTP 保存兼容修复

首次线上完整流程发现，`CosmicExperience.saveJournal` 直接调用仅在安全上下文可用的 `crypto.randomUUID()`，HTTP 公网预览因此抛错，尚未发出保存请求。

新增 `src/lib/journal-id.ts`：可用时保留原生 UUID；否则以 `crypto.getRandomValues` 生成符合 UUID v4 格式的手记 ID。没有使用 `Math.random`，没有增加依赖或修改视觉、动效、手记协议及认证方案。此 ID 用于记录标识，不承担认证凭据的作用。旧前端未使用的 `TarotExperience` 不在本次修改范围。

先用缺失 `randomUUID` 的浏览器环境测试复现同样错误，再修复；新增测试覆盖原生路径及 HTTP 路径下 ID 格式和区别。服务器组件文件及辅助模块的规范化 SHA-256 与本地相同。

## 运维与后续更新

日常启停在“网站 → Node 项目 → tarot-preview → 设置 → 服务”进行。另添加并启用 `tarot-preview-boot.service`，以 `www` 调用同一宝塔启动脚本，类型为 oneshot，只承担开机入口，不是第二个长期进程管理器。已在应用停止后手动启动该单元，页面恢复且 SQLite 记录保留；未进行整机重启。不要重复执行启动脚本，异常退出后的自动拉起本轮未实现。

备份工具 `/usr/local/sbin/tarot-sqlite-backup` 使用 SQLite 在线备份 API，输出至 root 私有的 `/var/backups/tarot/`。每日 03:15（服务器时间）由 `/etc/cron.d/tarot-sqlite-backup` 执行；当前为同机备份，没有异地备份或自动清理。首份备份及独立恢复副本通过 `integrity_check`，记录数量与原库一致。

日志位置：`/www/wwwlogs/nodejs/tarot-preview.log`、`/www/wwwlogs/tarot-preview.log`、`/www/wwwlogs/tarot-preview.error.log`。`/etc/logrotate.d/tarot-preview` 配置每日检查、10 MiB 提前轮转、保留 7 份及压缩、copytruncate。调试检查发现 `/var/log` 的父目录组权限要求明确指定 `su root root`，已补充并复核。宝塔原生启停可能重设项目日志权限；当前校正为 640，开机单元也包含权限校正。
