# AUTH-001：香港 ECS 登录安全架构评估

日期：2026-11-16。状态：架构评估与后续实施基线；认证代码尚未接入。

- 登录第一版采用邮箱＋密码，包含邮箱验证、退出、忘记密码和重置密码。
- 目标为用户已有的阿里云中国香港 ECS，暂未准备域名，后续正式部署上线。
- 已读取用户指定的另一个项目部署对话（thread `01a1e23e-3666-71a3-9407-18f7d654ed46`），确认配置为经济型 e、2 核 4 GiB、40 GiB 系统盘，用户偏好宝塔可视化管理；读取时该对话正在安装宝塔。
- 本轮以用户截图和部署对话为依据，没有通过 SSH 或浏览器操作服务器，也没有读取密码、私钥或应用密钥。
- 星空维持现状，真实 AI 解读仍最后接入。

## 3. 首版部署结构

```text
浏览器
  → HTTPS 域名
  → 宝塔管理的 Nginx（证书、反代、请求体限制、入口限速）
  → 127.0.0.1:3000 单个 Next.js／Node.js 24 应用
       → Better Auth（用户、凭据、会话、验证与重置）
       → 按会话用户隔离的手记接口
       → SQLite 持久目录
       → 外部 SMTP 发信服务
```

沿用宝塔路线，采用一个明确的进程管理入口，不同时叠加一套 Caddy／容器入口争用 80／443，也不重复启动多个同名应用。应用用专用普通用户运行；系统安装与维护可由管理员执行。

数据库建议部署到 `/var/lib/tarot/` 等非公开持久目录，通过 `TAROT_DATABASE_PATH` 指定；应用发布目录与数据库分离。密钥由服务器环境配置，限制读取权限并排除 Git、上传包、静态目录和日志。更新代码不能替换日常数据库。

SQLite 首版保持单应用实例。未来需要多实例或明显增加写入并发时，再实施 PostgreSQL 适配与数据迁移；这不是只换连接字符串的工作。

## 4. 认证与会话

采用 Better Auth，由库承担密码哈希、会话及验证流程。正式引入前确认当前 Next.js／React／Node 兼容版本、依赖安全及安装脚本策略，锁定版本后接入；不因架构选择宣称该依赖已经安装或通过审计。

- 邮箱作为登录标识，注册邮箱必须验证；昵称作为独立显示字段。
- 首版无 MFA 的密码策略按 OWASP 长口令建议：至少 15 字符、最多 128，允许空格和 Unicode，不截断密码、不强制周期改密；允许密码管理器粘贴。实现时校验长度语义及常见弱密码阻断。
- 使用库的 scrypt 实现和参数，密码哈希保存在认证 `account` 数据中；用户表不保存明文密码。
- 数据库保存会话，浏览器携带 HttpOnly Cookie；公网 HTTPS 配置 Secure、SameSite=Lax，保持站点与认证 API 同源。
- 首版会话有效期 7 天、最多每天续期；退出撤销当前会话，重置密码撤销全部旧会话，敏感账户操作要求重新认证。
- 初期关闭会话 Cookie 缓存，使撤销结果直接由数据库生效；后续启用缓存时必须评估撤销延迟。
- 生产站点地址和可信来源显式配置，只信任实际反代；不由任意客户端 Host／转发头推导重置链接或认证域名。
- 开发使用本地开发地址；正式环境配置不完整时明确拒绝启用认证，不为临时公网 IP 访问关闭验证、Cookie 或来源保护。

## 5. 用户数据隔离与迁移

当前 `/api/journals` 未验证身份，`GET` 返回共享资料库；现有同源检查不等于用户认证。本地单人实现不能直接当作多用户公开服务。

认证库管理 `user`、`account`、`session`、`verification`。业务数据迁移为：

- `journals`：主键包含 `user_id, kind, id`，用户外键与时间索引。
- `journal_cards`：外键包含同一 `user_id`，绑定该用户的具体手记。
- `legacy_imports`：幂等和删除防复活账本按 `user_id, legacy_id` 隔离。
- 数据访问方法显式传入服务端会话得到的用户 ID：`list(userId)`、`save(userId, record)`、`delete(userId, kind, id)`。
- 全部读取、插入、删除都带用户条件；请求中的用户 ID 不能决定归属。未登录返回 401，其他用户的记录按不存在处理。
- 切换账户／退出立即清理历史及保存状态、取消旧读取；异步响应核对账户与操作代次。

既有共享数据库先一致性备份并隔离归档，由项目所有者明确指定目标账户后再迁入；不能自动划给第一个注册者。浏览器旧手记改为登录后主动选择导入，展示数量和预览，保留原数据；不继续在每次打开历史或切换账户时自动导入。

未登录仍可体验占卜与百科，保存／个人历史要求登录；登录交互保留当次抽牌和解读状态。首版不上匿名共享手记池。

## 6. 登录攻击及邮件滥用防护

- 对注册、登录、验证邮件和找回密码分别配置限速，覆盖来源 IP 和账户标识；限制密码哈希并发，按 2 核环境测定参数。限速状态需考虑进程重启，不能只依赖页面按钮禁用。
- Nginx 覆盖客户端传入的来源头，Node 3000 仅绑定本机；认证只使用该可信代理提供的来源。后续引入 CDN 时重新配置可信代理链。
- 登录失败、注册重复邮箱、找回密码等响应考虑账户枚举；找回密码采用一致提示，不暴露账户是否存在。
- 邮箱验证／密码重置链接使用库支持的受保护令牌及明确有效期；密码重置令牌一次使用，事务完成密码更新及会话撤销，并验证重放与过期失败。
- 不记录密码、完整会话令牌、验证链接或完整请求表单；安全日志仅保留必要事件及脱敏标识。
- 个人历史与认证响应禁止共享缓存，明确 CSRF／来源和回跳地址校验。

外部 SMTP 支持加密连接；阿里云 ECS 默认限制公网 25 端口，首选发信服务支持的 465 加密端口。正式域名准备后配置邮件域名验证、SPF／DKIM 及投递测试；开发验证使用本地邮件测试环境或受控 mock，不向真实收件人自动发送测试邮件。

## 7. 上线边界与运维

- 香港资源无需办理中国内地 ICP 备案；正式邮箱注册建议先具备域名、HTTPS 证书及验证过的发信配置。本地代码和测试不受当前未有域名的阻碍。
- 公网网站入口只开放 80／443；SSH、宝塔管理入口限制管理员来源，应用端口及数据目录不对公网暴露。
- 当前截图为 root 管理终端，不能据此判断应用已以 root 运行；部署时专门验证站点进程权限。
- Ubuntu 22.04 当前仍在标准维护期，上线前检查系统补丁、依赖安全与宝塔版本；升级操作由部署流程管理，非本轮远程操作。
- 备份使用 SQLite 一致性备份方式或停写备份，保存加密异机副本；上线前演练恢复。恢复后清理旧会话与未完成的重置／验证状态，避免恢复历史撤销状态。
- 明确宝塔／进程管理器开机恢复、日志轮转、磁盘告警和健康检查。构建可在服务器或同架构 Linux CI 完成，不上传 Windows 的 `node_modules` 作为 Linux 运行环境。
- 登录不替代未来 AI 成本保护；真实 AI 接入时还需按用户及全站限制调用、并发和总额度。
- 在认证／手记隔离完成前，服务器预览保持访问限制，真实 AI 关闭；不把当前共享手记接口当作正式公开版本。

## 8. 实施顺序与验收

1. 明确认证库兼容版本与迁移 SQL，备份现有数据；接入用户、会话与邮箱流程。
2. 迁移手记归属、导入账本和全部 API 授权，补账户切换及异步隔离。
3. 将演示昵称替换为注册／登录／验证／找回密码界面，保留现有占卜状态。
4. 本地受控邮件联调，测试正常及过期／重用／失败场景；最终域名和发信配置具备后做真实投递验收。
5. 与部署对话衔接宝塔／Nginx、HTTPS、可信代理、权限、持久目录和恢复验证，再开放注册。

必须验证：

- A／B 两账户及相同手记 ID 的读取／删除／导入互不影响，伪造用户 ID 无效。
- 未登录访问个人接口失败；退出、会话过期及密码重置后的旧会话均不可用。
- 验证和重置令牌过期／重用失败，重置事务失败不留下半完成状态。
- 恶意 Origin、回跳地址及伪造来源头不能绕过保护或限速。
- 同浏览器切换账户不会显示上个账户的数据或自动导入旧手记。
- 重启后账户和手记保留；代码更新不覆盖数据；可从备份恢复。
- 记录生产运行、构建峰值、登录哈希资源与国内访问实测，不凭内存总量承诺并发容量。
