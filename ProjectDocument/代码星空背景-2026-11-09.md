# 代码星空背景

用户反馈全景图片在实际页面中过于杂乱，决定先尝试纯黑背景与独立闪烁的星点。此版本用于观察页面实际效果，不继续生成或放大全景图片。

## 当前实现

- 使用现有 Three.js 场景、相机与渲染时钟，移除背景平面、贴图球壳及叠加的旧星点；卡牌图片与交互继续使用原有实现。
- `src/lib/cosmic-starfield.ts` 用一个点云绘制全周共 4590 个星点：3825 个远星、612 个中景星点和 153 个较近星点。此前由 1800 个增加 50% 至 2700 个，2026-11-10 再追加 70%（1890 个），原有星点保留。小而暗的星点占多数，少量亮星辅助辨识空间。完整场景数量不等于单个视角同时显示的数量。
- 远星距离镜头 800–920，只响应镜头转向，作为稳定的天空参照。中近景的空间中心沿实际穿行路线分布，分别偏移 300–460 和 85–175 世界单位，位置固定，随镜头平移产生不同强度的视差。距镜头 64 至 28 世界单位范围内逐渐隐去，防止贴脸闪过。星光以 2.5–5.5 秒主周期独立闪烁，亮星幅度更明显，保留暗部底光，不整体同步闪灭。
- 页面底色与 WebGL 清屏色均为纯黑。星空不使用星云或星系图片、噪声纹理或镜头光斑，也不再加载历史全景资源。2026-11-10 起另外加入 4 团代码生成的极淡局部体积星雾，见下方首版记录。
- 星点复用既有动画循环；减少动态效果模式固定星光亮度，页面隐藏时跳过 WebGL 绘制。WebGL 不可用时保留纯黑底与原有卡牌降级交互。
- 历史图片继续保存在 `public/assets/cosmic/` 中备选，当前不引用。

## 评估与取舍

代码星点更方便控制密度、大小、亮度和动态，便于为卡牌与文字保留清楚的空间，并消除了全景纹理自身的接缝和极点问题。其画面辨识度和星云层次较少；持续闪烁也需要持续绘制，不能在没有测量的情况下声称性能更好。先验证基础星空的阅读和交互效果，再判断是否有必要增加极淡雾层。

## 初版验证

- 相关单元测试：4 个文件、25 项通过，覆盖相机、首页流动、空间牌流和圆环。
- TypeScript 类型检查与改动代码 ESLint 通过；调整亮度后再次检查星空模块 ESLint。
- 浏览器实际走通：首页、提问、抽牌、逐牌解读、整体总结；正常抽牌阶段星空时钟继续前进。
- 桌面、手机与 WebGL 不可用场景均核对；减少动态效果下星空时钟为 0，稳定画面不持续重绘。
- WebGL 上下文丢失后恢复成功；本轮功能检查没有页面异常或控制台错误。减少动态效果测试会产生 Framer Motion 的预期提示。
- 网络检查：全景图片请求为 0。
- 对同一片无界面星空区域间隔 1.8 秒截图比较：620×160 区域有 41 个星点像素改变，最大单通道变化为 12；黑底占 99.934%。确认存在克制的实际像素变化，而非只更新时钟属性。
- 截图与检查脚本保存在忽略目录 `output/playwright/`，包括 `procedural-stars-home.png`、`procedural-stars-question.png`、`procedural-stars-reading.png`、`procedural-stars-mobile.png`。

手机截图也显示已有首页标题和按钮布局的裁切；这属于并行的首页 UI 调整，本次未修改其排版。背景检查通过不代表已完成整体手机端布局验收。

## 远近层次优化

用户选定“远近层次：用少量较近星点与远处星海形成更自然的视差，保持疏朗”。本轮只修改星空生成模块，纯黑底、总体星点数量、闪烁规则和卡牌镜头交互保留。

远层在顶点着色器中补偿镜头位置变化，因此平移时位置稳定。中近层使用世界坐标，沿完整镜头路线分布；近层点大小有上限，并使用按镜头距离变化的透明度，避免突然放大。整个背景仍是一个点云与现有渲染循环。

验证使用实际源码经 TypeScript 转译后的模块，不另写一份星空算法。在隔离的 WebGL 画布中冻结闪烁，相同相机朝向、相同路径位置（穿行进度 0.5）、相同横向位移 20 世界单位、相同 960×600 画布下：

| 层次 | 两帧均在画面内的样本数 | 投影位移中位数 |
| --- | --- | --- |
| 远星 | 104 | 0 像素 |
| 中景 | 16 | 30.41 像素 |
| 较近星点 | 10 | 66.12 像素 |

GPU 截图对照也确认远层两帧完全一致，中近层实际像素发生变化；不是仅修改名称或调试属性。单独一个近星在距镜头 80 单位时可见（16 个发光像素，最高通道值 122），距镜头 10 单位时为全黑，验证近距离渐隐生效。

另对七个穿行位置采样，视锥内较近星点数为 6、1、4、13、6、1、0；保留自然疏密和空白，没有强制让每个方向都填满近星。

本轮 TypeScript 类型检查和星空模块 ESLint 通过。实际页面再次走通首页、提问、抽牌、解读、总结；减少动态效果下时钟为 0 且帧数稳定，WebGL 上下文恢复正常，背景图片请求为 0，检查期间没有页面异常或控制台错误。桌面和手机端已观察背景；手机首页已有排版裁切仍由并行 UI 工作处理。

检查脚本与截图位于 `output/playwright/`，包括 `check-star-depth.js`、`star-depth-qa.html`、`depth-*-a.png`、`depth-*-b.png`、`check-layered-stars.js` 和 `layered-stars-*.png`。隔离画布只用于验证，不增加产品页面或入口。

## 星光闪烁优化

用户要求先强化星星“一闪一闪”的动态，完成后再讨论其他宇宙元素。本轮仅调整星光时间参数与亮度曲线：主周期由 5–12 秒改为 2.5–5.5 秒，弱星幅度较柔和，中亮星幅度更明显；每颗星具有独立相位，并叠加轻微节奏变化。保留最低亮度，平滑变亮与变暗，不硬切闪灭，也不改变星点大小。

通过前后源码生成的几何属性逐字节对照，确认位置、大小、基础亮度、颜色、视差属性全部相同；总数、空间布局和远近关系保留。隔离 GPU 画布对同一颗亮星的 25 次时间采样，实际像素峰值在 76–220 之间变化，确认明暗变化明显且暗时仍可见。不同时间的星空截图有变化，相同时间重复绘制的截图完全一致。

实际页面确认间隔 1 秒的星空像素发生变化，总数仍为 1800；减少动态效果模式下时钟为 0、帧数与像素均稳定。本轮无页面异常、控制台错误或背景图片请求。ESLint 与默认类型检查通过。类型检查最初纳入了 `output` 内其他任务的旧代码快照，因此在 `tsconfig.json` 中排除生成目录 `output`；当前应用和正常测试仍接受检查，没有删除或修改那些快照。

本轮检查脚本为 `output/playwright/check-star-twinkle.js` 与 `check-live-twinkle.js`，截图包括 `twinkle-sky-*.png`、`twinkle-live-*.png`。其他宇宙元素尚未加入。
