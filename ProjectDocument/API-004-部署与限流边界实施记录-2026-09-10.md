## 1. 结论

API-004 已完成可提交的工程实现，部署方案确定为 **Vercel Node.js Functions + Upstash Redis REST**。限流状态不保存在 Next.js 进程内，而是通过 Upstash Redis 和原子 Lua 脚本共享，因此可以覆盖 Serverless 横向扩容和多实例并发。

当前保护规则为：

- 每个匿名客户端标识最多 **5 次有效解读请求 / 10 分钟**。
- 每个匿名客户端标识最多 **1 个正在执行的解读请求**。
- 频率超限返回 HTTP `429`、错误码 `READING_RATE_LIMITED` 和 `Retry-After`。
- 并发超限返回 HTTP `429`、错误码 `READING_CONCURRENT_LIMIT` 和 `Retry-After`。
- 生产环境中，限流配置缺失、可信客户端地址无效或 Redis 不可用时返回 HTTP `503`、错误码 `RATE_LIMIT_UNAVAILABLE`；不在保护失效时继续消耗 DeepSeek 余额。
- Redis 键只包含部署环境命名空间和客户端地址的 HMAC-SHA256，不保存原始 IP，不包含用户问题或卡牌内容。

## 3. 部署环境决策

| 维度 | 决策 | 原因 |
| --- | --- | --- |
| 应用平台 | Vercel | 与当前 Next.js App Router 直接匹配，部署和预览环境清晰 |
| 函数运行时 | Node.js Functions | 当前代码依赖 `node:crypto`、`node:net`，并需要执行服务端 DeepSeek 和 Redis 请求 |
| 限流状态 | Upstash Redis REST | Serverless 进程会扩缩容，内存状态不能跨实例；REST 客户端适合短生命周期函数 |
| 原子决策 | 一段 Lua 同时处理频率与并发 | 避免多个 Redis 往返之间出现竞态 |
| 客户端身份 | Vercel 覆写后的 `x-forwarded-for` 首个 IP，经 HMAC-SHA256 派生 | 不接受浏览器自报 ID，不在 Redis 保存原始 IP |
| Preview/Production 隔离 | Redis 键使用 `VERCEL_ENV` 命名空间 | 避免预览流量消耗生产限额；条件允许时仍建议使用独立 Redis 凭据 |
| 失败策略 | 生产环境 fail closed | Redis 或信任配置异常时停止调用收费上游，避免无保护消耗 |

Vercel 官方说明 Functions 会按请求扩缩容，因此单进程 `Map` 无法作为生产共享保护。Vercel 还会覆写 `x-forwarded-for`，以防请求者伪造该值；本实现只在明确配置 `RATE_LIMIT_TRUSTED_PROXY=vercel` 后信任这个头。Upstash Redis 通过 REST 提供共享状态，并支持带 key locking 标记的 Lua 脚本。

- [Vercel Redis integrations](https://vercel.com/docs/redis)

## 4. 信任边界

### 4.1 信任的输入

生产环境只信任：

1. Vercel 直接转发给函数的 `x-forwarded-for`。
2. 值中第一个、且能通过 Node.js `isIP` 验证的 IPv4 或 IPv6 地址。
3. 服务端私密环境变量 `READING_RATE_LIMIT_SECRET`。

### 4.2 不信任的输入

- `x-real-ip`。
- `x-vercel-forwarded-for`。
- Cookie、本地存储 ID、请求体中的用户 ID。
- 问题文本、牌 ID 或其他业务字段。
- 未经评估的外部 CDN、反向代理或负载均衡器追加的转发链。

如果未来在 Vercel 前方增加 Cloudflare、Nginx 或其他代理，必须重新定义哪个组件负责覆写客户端地址，不能沿用当前信任假设。未经复核，不得把这个接口暴露在会保留用户自带 `x-forwarded-for` 的代理链后方。

### 4.3 匿名标识与隐私

匿名标识计算方式：

```txt
HMAC-SHA256(READING_RATE_LIMIT_SECRET, trustedClientIp)
```

Redis 键格式：

```txt
tarot:reading:v1:{preview|production}:{64位十六进制HMAC}:rate
tarot:reading:v1:{preview|production}:{64位十六进制HMAC}:active
```

要求：

- `READING_RATE_LIMIT_SECRET` 至少 32 个 UTF-8 字节。
- Secret 不能以 `NEXT_PUBLIC_` 开头，不能提交到 Git。
- 轮换 Secret 会让现有限流桶失效，相当于清空匿名限额；应在低流量窗口有意识地轮换。
- 当前代码不会把原始 IP 或问题写入 Redis，也没有新增请求日志。

IP 仍属于可能涉及隐私的网络标识。虽然这里只保存带服务端密钥的 HMAC，公开发布前仍应在隐私说明中披露“为防滥用而短期处理匿名化网络标识”，该工作归 `DOC-001`。

## 5. 限流规则

### 5.1 频率限制

- 限额：5 次。
- 窗口：10 分钟。
- 算法：首次有效请求创建带 600 秒 TTL 的计数器，后续请求共享该到期时间；这是“从首次请求开始的固定 TTL 窗口”，不是逐请求滑动窗口。
- 第 6 次及以后在当前窗口内返回 429；被拒请求不会延长窗口。
- `Retry-After` 等于当前计数器剩余 TTL 向上取整后的秒数，最小为 1。

当前 5/10 分钟是面向毕业设计演示和有限 DeepSeek 余额的保守初始值。它是可审查的代码常量，不允许通过浏览器参数修改。真实流量数据出现后，如需调整，应作为独立变更更新本文和测试。

### 5.2 并发限制

- 同一匿名标识最多 1 个活动请求。
- 成功获取后创建随机 UUID 令牌和 35 秒 Redis 租约。
- DeepSeek 当前超时为 30 秒，租约多保留 5 秒，覆盖正常超时清理和少量网络抖动。
- 请求无论成功、已分类上游错误还是未知异常，路由 `finally` 都会尝试用令牌释放租约。
- 释放脚本只有在 Redis 中令牌仍与本请求一致时才删除键，旧请求不能误删新请求的租约。
- 释放失败不会覆盖已经产生的读取响应；租约最迟在 TTL 到期后自动清除。

### 5.3 计数时机

请求处理顺序为：

```txt
请求体字节限制
  -> JSON/领域校验
  -> 共享频率与并发决策
  -> DeepSeek 调用
  -> finally 释放并发租约
```

这意味着非法 JSON、超大请求、未知牌或其他 400/413 请求不会访问 Redis，也不会消耗 5 次额度；只有已经通过领域校验、准备调用 AI 的请求才计数。DeepSeek 配置错误、上游错误或格式错误仍会计数，因为它们已经进入收费服务边界。后续是否对特定服务端故障退还额度属于成本策略，不在本任务中隐式处理。

## 6. Redis 原子决策

`src/lib/reading-rate-limit.ts` 使用单个 `EVAL` 脚本完成以下操作：

1. 检查活动租约；存在则直接返回并发 429，且不增加频率计数。
2. 增加频率计数，并在首次请求时设置窗口 TTL。
3. 超过频率限额则返回频率 429。
4. 未超限时创建带随机令牌的活动租约。
5. 返回是否允许、拒绝原因、剩余额度和对应 TTL。

脚本头使用 Upstash 支持的 `#!lua flags=allow-key-locking`，确保同一组键上的决策不会被并发请求交错。这里没有采用“先 GET 再 INCR 再 SET”的多命令应用层逻辑，避免两个 Serverless 实例同时放行同一用户。

Redis REST 请求配置：

- 禁用遥测。
- 禁用自动流水线，保持每次限流决策边界清晰。
- 结果不使用 Base64 编码，因为 Lua 返回的是数字数组。
- 单次请求使用 2 秒 `AbortSignal`；超时会真正中止 fetch，不留下在 503 响应之后继续运行的后台限流写入。
- 最多重试 1 次短暂网络失败。

## 7. API 错误契约

所有错误继续沿用：

```json
{
  "error": {
    "code": "STABLE_ERROR_CODE",
    "message": "中文可读信息",
    "retryable": true
  }
}
```

| 场景 | HTTP | code | retryable | 附加响应头 |
| --- | ---: | --- | --- | --- |
| 10 分钟内超过 5 次 | 429 | `READING_RATE_LIMITED` | `true` | `Retry-After` |
| 同一标识已有请求执行 | 429 | `READING_CONCURRENT_LIMIT` | `true` | `Retry-After` |
| Redis/Secret/代理信任配置不可用 | 503 | `RATE_LIMIT_UNAVAILABLE` | `true` | 无 |

这里的 `READING_RATE_LIMITED` 是应用自身保护，与 DeepSeek 返回 429 时映射的 `DEEPSEEK_RATE_LIMITED` 区分，便于前端和未来监控判断故障来源。

## 8. 环境变量

```env
DEEPSEEK_API_KEY=your_api_key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash

RATE_LIMIT_TRUSTED_PROXY=vercel
READING_RATE_LIMIT_SECRET=at_least_32_random_utf8_bytes
UPSTASH_REDIS_REST_URL=https://your-database.upstash.io
UPSTASH_REDIS_REST_TOKEN=your_rest_token
```

行为说明：

- `next dev`（`NODE_ENV` 非 production）旁路共享限流，避免本地开发依赖云服务。
- `next start`、Vercel Preview 和 Vercel Production 都会启用保护；配置缺失时有效请求返回 `RATE_LIMIT_UNAVAILABLE`。
- `RATE_LIMIT_TRUSTED_PROXY` 当前唯一合法值为 `vercel`，这是有意的部署锁定，不应改成任意布尔值。
- `UPSTASH_REDIS_REST_TOKEN` 和 `READING_RATE_LIMIT_SECRET` 都是服务端 Secret，不得写进客户端 bundle、日志或截图。

## 13. 回滚与风险

### 13.1 回滚

如代码引发回归，可整体 revert 本任务提交，恢复 API-003 后的请求流程。不能只删除环境变量却保留生产限流代码，否则所有合法生产请求都会按预期 fail closed 为 503。

### 13.2 已知风险

- IP 级限流可能让同一校园网、公司网或家庭 NAT 后的多人共享额度；匿名、无账号产品无法完全避免该权衡。
- IPv6 临时地址可能降低单 IP 限流稳定性；后续若出现真实滥用，可评估前缀归一化或附加签名 Cookie，但不能仅信任客户端 ID。
- 固定窗口在边界两侧允许短时间内最多约两倍突发；当前并发 1 可限制同一标识的即时费用峰值。若真实数据表明仍不足，再评估滑动窗口。
- Upstash 成为在线解读的可用性依赖；当前选择 fail closed 是成本安全优先，未来监控和故障预案归 API-005/REL-002。
- 35 秒租约依赖 DeepSeek 超时继续保持在 30 秒以内；任一超时调整都必须同步复核租约 TTL。
