## 2. 实现范围

使用现有 React、Next.js、Framer Motion、Lucide 与真实 RWS 素材，没有增加依赖。

`CosmicExperience.tsx` 管理阶段、表单与面板；`CosmicScene` 始终挂载全景、轨道和 78 个独立牌平面。以每张牌的牌组索引作为轨道锚点，统一圆环角度、投影与镜头插值连接开场、洗选、阅读及总结。当前是浏览器中的 2.5D 原型，并非 Three.js/WebGL 完整三维空间。

流程已连接：

1. 星空中卡牌飞入、独立待机，显示命运回廊与开始占卜入口。
2. 同场景打开准备面板，选择牌阵并填写问题。
3. 镜头推进；Fisher–Yates 实际洗牌，逐张固定正逆位，牌流汇入旋转圆环。
4. 选牌按 N 计数；原位序号、约 6.5% 缩放与边缘光，不抬升、不飞入新槽位。
5. 左键拖拽整环、带短暂惯性；移动超过 7px 判为拖拽，结束时拦截点击，未添加任何拖拽提示文案。拖动不洗牌，也不改变选中身份、索引、牌位或正逆位。
6. 抽齐后镜头缓慢抬高为斜俯视，进入同一全景的星门局部；整环走最短角度将当前锚点带到左前方，停稳后原地翻面。未选牌仍在场景中，不额外整体暗化。
7. 上一张／下一张手动推进，切换期间短暂禁用推进按钮；牌位、牌名、方向、牌义与示例提问同步更新。
8. 最后一张点击查看整体解读，再经舒缓转场进入命运手记；可回看各牌、保存本次浏览示例、再次占卜。

主导航提供塔罗百科（78 张真实牌、搜索、大小阿尔卡那筛选、关键词详情）、历史记录（只读兼容旧版记录及本次浏览的示例）、昵称演示身份（仅 React 会话状态，无真实注册/认证）。使用原生 dialog 管理焦点与 Escape 关闭，提供可见焦点样式与减少动态效果偏好。

## 3. 牌阵草案与未接通内容

| 牌阵 | N | 语义牌位 |
| --- | --- | --- |
| 单牌 | 1 | 核心提示 |
| 是非牌 | 1 | 倾向与提醒 |
| 过去现在未来 | 3 | 过去／现在／未来 |
| 三牌阵 | 3 | 现状／阻碍／建议 |
| 十字牌阵 | 5 | 现状／阻力／根源／建议／走向 |
| 恋人十字牌阵 | 5 | 我方状态／对方表现／关系现状／阻碍／发展 |
| 暗恋牌阵 | 4 | 我的心意／对方可观察信号／距离与阻碍／行动建议 |
| 心之声 | 4 | 表层感受／深层需要／未表达的担忧／自我建议 |

这属于前端配置草案，不宣称是唯一或通行的塔罗规则。当前全部使用原轨道选牌、序号和语义牌位区分；没有把卡牌移成十字形，也未实现是非判定算法。这些仍待用户看过运动原型后确定。

新前端从不调用 `/api/reading`；“示例解读”“示例总结·仅供体验”有明确标识，不是 API 错误后的伪造降级。问题对应内容仅展示自我提问模板，不是真实 AI 分析。

示例手记只保留本次浏览内存，刷新即清空，不写进旧三牌存储键。真正的多牌阵 AI、带牌阵身份的持久化、迁移、认证仍需后续工作；旧 API 完整流程继续通过 legacy 入口访问。

## 4. 素材与验证

新增全景与透明轨道分别为独立 Image Gen 素材，规格和来源见 `public/assets/cosmic/README.md`。没有把概念网页整图贴入界面，没有新建第三方服务或部署。

验证入口：

- `npm test`：原有保护与新增圆环领域测试。
- `npm run check`：Lint、类型及构建。
- `npm run test:e2e`：新版三牌完整闭环、全部其余牌阵的 N 张选择与手动阅读、旧版 mock AI／保存刷新闭环；禁止真实付费 AI。
- 应用内浏览器：实际输入、选牌、拖动、回看、总结转场、示例历史、百科搜索详情、演示身份和控制台检查。
- 根目录 `design-qa.md`：源概念与实际页面的全图／局部合并对比及修正记录；截图位于忽略的 `output/frontend-v2/`。

实际结果：171 项单元／接口测试通过；`npm run check` 通过；新版浏览器 8 项全部通过，旧版 1 项核心闭环通过。最终在默认 1280×720 视口检查，阅读正文可滚动，控制区固定在面板底部；不会因视口较矮而隐藏推进入口。

第一轮发现阅读对比不足、牌流过密、按钮字级覆盖、选牌文字与后排牌重叠，已据截图调整。首次全牌阵 E2E 未等待每次点击的 React 提交并只检查中心点，在重叠卡牌中漏选；其后又复现阶段提交早于投影首帧的等待问题，改为等待实际可命中的区域并逐次断言计数，未降低最终 N 张和闭环断言。最终复跑全部新版用例通过。

`next-env.d.ts` 仅有 Next 生产构建自动更新的两条类型导入，未手改生成内容。原 17 个未跟踪材料逐文件 SHA-256 与重建前备份一致，main 与旧版检查点指针未变。
