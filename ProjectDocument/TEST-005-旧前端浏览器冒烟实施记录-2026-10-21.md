## 1. 目标与工具

保留一条旧前端核心流程，验证真实浏览器能完成业务闭环，为后续前端讨论提供参考截图。继续遵守维护冻结边界，未修改 `TarotExperience.tsx`、业务样式或现有交互。

按既定选型精确安装 `@playwright/test@1.64.1`，其 Node.js 要求为 `>=20`，与项目 Node.js 24 兼容；传递依赖 `playwright`、`playwright-core` 同为 `1.64.1`。锁文件已用 npm `11.19.1` 更新，严格安装脚本审批列表为空。

仅安装并运行匹配版本的 Chromium 无头组件，不建立浏览器矩阵或旧 UI 快照库。

## 2. 运行方式

```text
npm exec -- playwright install --only-shell chromium
npm run test:e2e
```

`playwright.config.ts` 的 `webServer` 自动构建应用，在 `127.0.0.1:3000` 启动独立生产服务，结束后关闭；不复用已运行服务，端口被占用时直接报告错误。测试固定 1920×1080、单 worker、零重试。

服务环境显式设置 `DEEPSEEK_READING_ENABLED=false` 和空 Key，确保配置文件中的真实凭据不能启用解读。浏览器在导航前拦截 `/api/reading` 并返回本地 JSON，同时阻断并检查所有外部来源请求，禁用 Service Worker。

## 3. 单条流程与断言

`tests/e2e/reading-smoke.spec.ts` 覆盖：

1. 等待首页入场完成，输入固定的合成测试问题。
2. 点击开始，使用真实鼠标轨迹扰动洗牌。
3. 从当前最上层可拖卡牌依次拖入过去、现在、未来牌位，检查剩余牌数与阅读阶段切换。
4. 使用清楚标注的模拟文本，逐张等待打字机完成并继续揭示。
5. 进入手记，等待转场结束和三张真实牌面加载完成。
6. 点击保存，检查一条 localStorage 记录与实际提交的三牌 ID、方向、牌位及解读完全对应。
7. 刷新后打开历史记录，检查问题、总结和三张牌数量仍可读取。
8. 检查只有一次解读提交、三张牌 ID 不重复、请求只包含问题与公开卡牌选择字段，浏览器控制台错误、未捕获异常和外部请求均为空。

拖牌使用真实鼠标按下、分步移动与释放，不通过 React 内部状态或直接写 localStorage 绕过业务流程。等待通过 UI 状态、动画终态及图片加载断言完成，没有固定等待或降低断言。
