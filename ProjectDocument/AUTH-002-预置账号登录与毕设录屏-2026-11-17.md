# AUTH-002 预置账号登录与毕设录屏

日期：2026-11-17。用户为提交毕业设计演示视频和源代码，选择“预置账号的真实登录”。本轮实施邮箱密码校验、持久会话、退出和个人手记隔离。录屏在本地进行；正式邮箱注册、邮件验证、找回密码及公网 HTTPS 仍按 AUTH-001 后续实施。本地演示不接入付费 AI。

## 启动与账号

运行时继续使用 Node.js 24 和 npm 11.19.1。安装依赖执行 `npm ci`，录屏启动执行 `npm run demo`。命令初始化账号、构建生产页面并监听 `http://127.0.0.1:3000`。启动前检查端口，避免重复启动时重建仍在服务的 `.next`。`npm run demo:setup` 只初始化；`npm run demo:dev` 用于本地开发。

首次运行在 Git 忽略的 `data/demo/` 中生成：

- `accounts.json`：两个录屏专用账号及随机密码，仅供本机查阅。
- `.auth-secret`：随机认证密钥，后续重启复用以保持会话。
- `auth.sqlite`：认证用户、密码哈希、会话和限速状态。
- `journals.sqlite`：按用户隔离的个人手记。

认证数据库中的密码使用 Better Auth 的密码哈希实现。账号文件中的随机明文密码用于录制时输入，不是发布配置，不应出现在录像、Git 或源码包中。程序不会把密码打印到启动日志；初始化重复执行不会重设现有密码。账号文件缺失而库已有用户时明确停止，不覆盖数据库。

同日按用户要求追加一个本机账号。账号清单允许非空、邮箱唯一的多个账号，不再限定恰好两个；手工预置密码支持 12–128 位，默认自动生成的随机长密码不变。实际 HTTP 验证了新账号登录、会话身份、个人手记访问和退出撤销，重复初始化保留账号。自定义邮箱与密码不写入 Git 文档或测试。

追加账号专项：使用合成数据验证 11 位密码拒绝、12 位成功创建并在重开数据库后登录；52 项认证测试、相关 ESLint、全项目类型检查及生产构建通过。重建并重启本机录屏站后，再次实际确认新增账号可登录并获得正确身份。更新后全量离线测试为 424/425，唯一失败仍为下文记录的原有首页坐标断言。

`TAROT_DEMO_DATA_DIR` 可指定另一独立演示目录。旧共享 SQLite、旧浏览器记录和远端数据均保留；没有把共享记录自动归给首个登录者。重置演示应先备份、另选新目录，不在程序中自动删除记录。

## 后端边界

使用精确锁定的 Better Auth 1.7.25 与 Node 内建 SQLite，没有自写密码算法。脚本使用同一配置工厂，通过仅限初始化进程的注册能力创建账号；HTTP 服务关闭注册，并仅开放登录、会话读取和退出三个路径。

`TAROT_AUTH_MODE=local-demo`、显式回环 HTTP 地址和随机密钥必须配置完整。配置缺失或非回环地址时拒绝启用；此配置不用于公网部署。启动器清空真实 AI 密钥并显式关闭在线解读。没有修改 `.env.local`。

会话保存在数据库，Cookie 设置 HttpOnly、SameSite=Lax，本地回环 HTTP 使用非 Secure Cookie；没有为公网 HTTP 放宽安全要求。会话有效期 7 天，每天续期，关闭会话 Cookie 缓存；退出后复制的旧 Cookie 不再可用。认证响应及个人手记禁止缓存。

登录路由核对显式 origin、Host 和写入来源，限制真实请求体字节数为 8 KiB，只把服务端覆盖的本机来源用于认证限速，不信任客户端转发头。登录限速使用数据库，限制同一入口每分钟 10 次，其他认证请求每分钟 120 次；重启不清空限速记录。注册、邮件和修改密码等未交付路径返回 404。

## 手记归属与页面状态

新建 `user_journals`、`user_journal_cards`、`user_legacy_imports` 表，主键及外键包含 `user_id`。旧共享表保持不变。读取、保存、删除都由服务端会话决定用户，忽略请求体、查询参数或用户头伪造的归属。匿名请求返回 no-store 401。

客户端不再自动导入旧 localStorage。原记录保持原样，待后续有预览与明确授权的导入流程再迁移。登录本身不会更改问题、选中的牌或正逆位；游客可以完整浏览百科与示例解读，在保存或查看个人历史时登录。

登录弹窗沿用暗金风格，包含邮箱密码、加载、错误反馈、密码显示、个人资料、退出和会话读取重试。历史按用户和会话重新挂载，退出或无法确认会话时卸载旧记录。异步保存按会话与操作标识隔离；会话中断后保留同一手记 ID 供显式重试，不自动重发，不将旧响应显示给新账号。
